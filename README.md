# ERP «Диполь»

Управленческий и производственный контур для ИП Поляков Д.Ю. (бренд «Диполь»):
заявки на кровельные работы, планирование выездов, материалы, ФОТ, документы,
техника безопасности, транспорт и управленческие кассы.

Заменяет распределённую модель Google Sheets: связи идут по ID объектов, а не по
текстовым адресам, правила направлений живут в данных, а не в формулах.

## Запуск

```bash
# 1. База
createdb dipol_db
psql -d postgres -c "CREATE ROLE dipol LOGIN PASSWORD 'dipol'"
psql -d postgres -c "GRANT ALL ON DATABASE dipol_db TO dipol"

# 2. Бэкенд (Java 21, Spring Boot 4, миграции Liquibase применяются при старте)
cd backend && SPRING_DATASOURCE_PASSWORD=dipol mvn spring-boot:run   # :8080

# 3. Фронтенд
cd frontend && npm install && npm run dev                            # :3000
```

Первый вход — `admin` / `foxy` (меняется через `APP_ADMIN_USERNAME` /
`APP_ADMIN_PASSWORD`). Дальше пользователями управляют из раздела «Пользователи».

Сборка одним артефактом: `npm run build` во `frontend`, затем `mvn package`
в `backend` — собранный фронт попадёт в `classpath:/static/`, приложение будет
раздавать и API, и интерфейс с одного порта.

## Что НЕ перенесено намеренно

**Формула выплаты вырубки РК-3.** В действующей таблице выплата считается по
производительности `p` вместо коэффициента `k` — это ошибка, зафиксированная в
бизнес-ТЗ как P0. Перенесён только исходный факт (принятые м², чел·ч); расчёт
выполняет ERP по правилу «часы × базовая ставка × k», где k берётся из
версионируемой таблицы диапазонов. Пока базовая ставка не утверждена
(конфликт 595 / 610), расчёт возвращает понятный отказ вместо числа.

**«Общий объём» из разнородных единиц.** В листах снега и наледи м², м.пог. и
штуки складывались в одну условную величину. В ERP каждая работа хранит свой
объём в своей единице; сводный показатель возможен только отдельной формулой.

## Ключевые решения модели

- **Дом** — внутренний неизменяемый ID. ФИАС и КЛАДР хранятся как внешние
  идентификаторы, текстовый адрес ключом не является. Любое написание адреса
  запоминается алиасом и в следующий раз сопоставляется автоматически.
- **Проект** разделён на два уровня: переиспользуемая *конфигурация* (работы,
  статусы, обязательные поля, чек-лист, допустимые схемы ФОТ) и *конкретный
  проект* у клиента. Новое направление запускается из интерфейса.
- **Схема оплаты** принадлежит связке «сотрудник + проект + период», а не
  проекту: в одном проекте одновременно работают люди за смену и сдельно.
- **Заявка** хранит проект, финансовый класс, статус выполнения и закрытие у
  заказчика четырьмя независимыми полями.
- **Спецтехника** — самостоятельная смена с распределением стоимости по
  адресам, а не атрибут выезда.
- **Материалы** проходят один складской журнал, включая сценарий «с колёс».
  Отмена — обратное движение, исходная операция остаётся.
- **Кассовая операция** имеет UUID; удаление проведённой операции запрещено,
  исправление — сторно.
- **Нормативы** (150 м²/подъезд, лимит 10 м², лимит белой ЗП) вынесены в
  версионируемые параметры с датой действия.
